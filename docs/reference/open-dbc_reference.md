# OpenDBC Reference

> Generated from `scripts/data/language_catalogue_editorial.json` by `scripts/generate_language_references.py`; do not edit this file.

OpenDBC preserves historical Classic and Professional behavior and adds a shared, opt-in desktop VR surface to both profiles. The 14 VR forms and Classic `X VECTOR3`, `Y VECTOR3`, `Z VECTOR3` readers are documented in [VR](../vr.md). Both profiles use `.dba`; `.dbpro` denotes a Professional project descriptor. [Usage](../usage.md) covers the command line and the keys of a running program.

## Documented engine choices

- `SET TEXT FONT name$, charset` uses Unicode fonts, so every character-set value selects the same glyphs.
- `MAKE STATIC OBJECT obj, 1` keeps the historical flag, but portable depth testing already produces the same visible occlusion result.
- Classic `LOAD IMAGE ..., texture mode` and `GET IMAGE ..., texturing flag` retain their compatibility hints while SDL_GPU uploads a full mip chain on demand.
- `STATIC LINE OF SIGHT ..., accuracy` uses an exact intersection test, so accuracy cannot change the result.
- `PERFORM CHECKLIST FOR GRAPHICS CARDS` lists the GPU driver selected by SDL.
- A requested 16-bit display remains logically RGB565 over the physical RGBA32 render target; project depth `16M` selects the 32-bit path.
- Classic `WRITE TO REGISTRY` and `GET REGISTRY` keep their values in `registry.json` in the user's OpenDBC storage folder (SDL's preference path) instead of the Windows registry; folder and key names ignore ASCII case.
- `3DBLIT AVAILABLE()` returns 1: every GPU draws 2D during 3D at full speed.
- Native pointers never cross into the VM; `GET MEMBLOCK PTR()` returns a [plugin address](../plugins.md#memblock-addresses).
- No MIDI bank ships: a failed `.mid` load tries the same name as `.mp3`, then `.wav` (`scripts/generate_dbc_midi_fallbacks.py`).
- Control-device commands use raw SDL joysticks. Missing rumble or haptic capabilities are no-ops; supported effects keep independent lifecycle-managed slots.
